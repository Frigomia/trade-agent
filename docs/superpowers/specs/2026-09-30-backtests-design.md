# Backtests screen and stored equity curve (sub-project 8b)

Sub-project 8b of the frontend roadmap in
`docs/superpowers/specs/2026-09-28-frontend-design-direction-design.md`. Sub-projects 2 to 6 and 8a
(`2026-09-30-secondary-screens-design.md`) are merged; Chat (7) is deferred by the owner. The backtest
engine and its API predate this spec (`2026-09-24-backtesting-design.md`); this spec adds the stored
curve the two-line chart needs, one read route, and the screen.

## Constraints

- The system never places a trade. The screen simulates on past prices only, offers no Buy/Sell, and
  says nothing is sent to a broker.
- Backend rules from `backend/CLAUDE.md`: thin routers, Pydantic v2 idioms, migrations only through
  `alembic revision --autogenerate` (never hand-edited), tests against real Postgres, no real yfinance
  calls in tests. Frontend rules from `frontend/CLAUDE.md`: named exports, `apiFetch`, SWR for reads,
  `useAction` for submits, no effects for derivable values, MUI 9 `slotProps`.
- Chart maths uses `d3-scale` and `d3-shape` only (individual modules, not the `d3` umbrella, no `d3-selection`); React renders every SVG element and d3 never touches the DOM. No other chart library.
- No currency symbol. Colour is never the only carrier of meaning. No exclamation marks or urgency
  wording.
- The existing engine numbers (signals, `final_value`, `buy_and_hold_value`, `excess_return_pct`,
  `hit_rate_by_signal`) must not change; existing engine tests stay green.

## Backend

### Engine

- `simulate(closes)` also records, for every trading day, the strategy value (`cash + shares * close`)
  and the buy-and-hold value (`STARTING_CAPITAL / closes[0] * close`).
- A pure `downsample(values, max_points=250)` returns the list unchanged when it already fits, otherwise
  evenly spaced points that always include the first and last value. Values are rounded to 2 decimals.
- `BacktestMetrics` gains `equity_curve: {"strategy": list[float], "buy_and_hold": list[float]}`, both
  lists the same length. The last strategy point equals `final_value` and the last buy-and-hold point
  equals `buy_and_hold_value` (up to rounding).

### Storage

- New nullable JSON column `backtest_results.equity_curve`, added by an autogenerated Alembic revision.
  Rows created before this change stay null. `jobs.run_job` writes the curve with the rest of the row.
- `docs/ARCHITECTURE.md` §4 (BacktestResult) and §5 (API table) are updated.

### Schemas and routes

- `BacktestResultOut` gains `equity_curve: EquityCurve | None`. It is used by the by-id route and by
  `/me/export`, so the export stays complete.
- New lean `BacktestListItemOut`: the existing `BacktestResultOut` fields without `equity_curve`.
- New `GET /backtest/results/{id}` returns `BacktestResultOut`, scoped to the caller; 404 when the row
  does not exist or belongs to someone else (same pattern as `GET /analysis/recommendations/{id}`).
- `GET /backtest/results?ticker=` now returns `BacktestListItemOut` rows, newest first (`created_at`
  descending, `id` descending as tiebreak), capped at 20. The ticker filter is unchanged.

### Backend tests

- Engine: curve lists have equal length; first and last day present; last points match the final
  values; a short series (under 250 days) is not downsampled; a long one is capped at 250; existing
  metrics unchanged.
- `downsample`: passthrough, cap, first and last kept, 0/1/2-element inputs.
- Routes: by-id returns the row with its curve; another user's row is 404; a row with a null curve
  returns `equity_curve: null`; the list is newest first, capped at 20 and carries no curve.
- Job: a finished job persists the curve.

## Frontend: `/more/backtests`

Page order: run form, result panel, recent runs.

### Run form

- Fields: ticker, From, To (date inputs), Run backtest button. Ticker is trimmed and uppercased before
  sending. Defaults: To is today and From is three years earlier (`todayIso`, UTC).
- Client validation mirrors the backend: ticker matches `^[A-Za-z0-9.\-^]{1,20}$`; From is not after To;
  the range is at most 30 years (10,950 days). Server errors show the API detail.

### Run and polling

- State is `{ jobId, selectedId }`; everything else is derived.
- Run POSTs `/backtest/run` (through `useAction`) and stores `jobId`.
- SWR polls `/backtest/run/{jobId}` every 2 seconds while the status is `RUNNING`, and stops on
  `DONE`, `FAILED` or an error.
- On `DONE`, `backtest_result_id` becomes `selectedId`, which drives `useSWR("/backtest/results/{id}")`;
  the recent-runs list is revalidated.
- On `FAILED`, or a 404 for the job (its Redis record expires after an hour), the screen shows: "The
  backtest could not run for that ticker and range. Check the ticker and dates." with the form ready to
  retry. The backend records no failure reason, so none is invented.
- The Run button is disabled while a job is running.

### Result panel

- Strategy final value against buy-and-hold final value, both from a 10,000 start (stated on screen),
  and the excess return as a signed percentage with a word (ahead of / behind buy-and-hold).
  `excess_return_pct` is a fraction: multiply by 100 for display.
- Two-line chart (`BacktestChart`, geometry in `lib/backtestChart.ts`): strategy (solid) and buy-and-hold
  (dashed) on one shared y scale with gridlines and y-axis tick labels, distinguished by dash style and
  a text legend naming each line, not colour alone. Hovering, or using the arrow keys, Home, End and Escape on the
  focused chart, shows a readout of both values for the nearest point ("Point k of n": the stored curve is
  downsampled); the nearest point comes from the inverted x scale, so `d3-array` is not needed. The x-axis is trading-day position, labelled with the run's
  start and end dates (the stored curve carries no per-day dates). The numbers shown beside the chart are
  its text alternative. When `equity_curve` is null (an older run) the chart is hidden and the numbers
  and table still show.
- Per-signal table: signal (in words), times seen (`count`), average move after 20 days
  (`avg_forward_return_pct` is a fraction, shown as a signed percentage), share that rose (`hit_rate`
  as a percentage). A small-sample note appears when any count is under 5.
- Copy: "Past performance is not a forecast. Simulated on past prices only; nothing is sent to a broker."

### Recent runs

`GET /backtest/results` (20 newest). Each row: ticker, date range, signed excess return with a word.
Selecting a row sets `selectedId`. Empty state: "No backtests yet."

### Logic module

`lib/backtest.ts` holds the types (`BacktestResult`, `BacktestListItem`, `EquityCurve`), the pure form
validation, `excessLabel` and `signalRows`; all unit tested.

### Frontend tests

Form validation (bad ticker, From after To, range over 30 years); run, polling and result with a mocked
`apiFetch` and fake `Date` timers; `FAILED` and job 404; selecting a past run; an old run with no curve;
signal table conversions and the small-sample note; chart geometry (shared scale, ticks, flat curve, nearest-point mapping); chart draws two paths with axis labels
and the numbers as text, plus hover and keyboard readout; the recent-runs empty state; load errors.

## Non-goals

Per-day dates on the curve, deleting or renaming runs, comparing two runs, extra strategy parameters,
running against a portfolio, zoom or brush on the chart, any chart library beyond `d3-scale`/`d3-shape`, changing the trading rules or the 10,000 starting value.

## Dependencies

`ARCHITECTURE.md` is updated in the same PR as the migration. Existing rows have a null curve; nothing
backfills them.
