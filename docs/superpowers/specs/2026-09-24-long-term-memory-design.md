# Long-Term Memory — Design Spec

Sub-project 3b of the analysis-agent evolution (ARCHITECTURE.md §15.1 step
3), building on 3a (local dev Postgres+`pgvector` migration, merged via
PR #9). This is the actual feature 3a existed for: store enough about each
past `Recommendation` and how it turned out that a future situation can be
matched against similar past ones and their outcomes.

## Scope

In scope:
- Four new columns on `Recommendation`: `price_at_recommendation`,
  `outcome_forward_return_pct`, `outcome_evaluated_at`, `embedding`.
- `backend/app/memory/embeddings.py` — Voyage AI client wrapper
  (`voyage-finance-2`, 1024-dim).
- `backend/app/memory/outcomes.py` — forward-return calculation, reusing
  `agents/market_data.fetch_quote_and_history`.
- `backend/app/memory/similarity.py` — `pgvector` cosine-distance query.
- `backend/app/routers/memory.py`: `POST /memory/embed`,
  `POST /memory/evaluate-outcomes`, `POST /memory/similar`.
- `agents/jobs.py`'s `_process_ticker`: pass the quote price already
  present in the graph's final state into
  `Recommendation.price_at_recommendation` when constructing the row. No
  change to `agents/graph.py` itself.

Out of scope:
- Wiring memory into the graph's actual decision-making — that's step 4
  (richer context assembly), deliberately last per ARCHITECTURE.md §15.1,
  and the reason this sub-project stops at storage + a queryable capability.
- Embedding `BacktestResult` rows. The original brainstorming's "backtest
  results" phrasing was one source of *outcome* data among others for a
  `Recommendation`-centered memory, not a second thing to embed — this
  spec's memory unit is `Recommendation`, full stop. `BacktestResult`
  stays exactly as it is, queryable via the existing `/backtest/results`.
- Any scheduler/cron. `POST /memory/embed` and `POST /memory/evaluate-outcomes`
  are manual, re-callable batch endpoints, matching `/analysis/run` and
  `/backtest/run`'s existing style.
- Backfilling `price_at_recommendation` for `Recommendation` rows that
  predate this migration — that price was never captured and can't be
  reconstructed after the fact. Those rows are skipped by
  `/memory/evaluate-outcomes` forever; a known, accepted gap.

## Data Model

Four columns added to `Recommendation` (`backend/app/models.py`):

```python
price_at_recommendation: Mapped[float | None] = mapped_column(Numeric(18, 6), nullable=True)
outcome_forward_return_pct: Mapped[float | None] = mapped_column(Numeric(8, 4), nullable=True)
outcome_evaluated_at: Mapped[datetime | None] = mapped_column(DateTime, nullable=True)
embedding: Mapped[list[float] | None] = mapped_column(Vector(1024), nullable=True)
```

`Vector` from the `pgvector.sqlalchemy` module (already a dependency as of
3a). 1024 is `voyage-finance-2`'s fixed output dimension. No ANN index
(`ivfflat`/`hnsw`) — exact cosine-distance search over a personal-scale row
count (low thousands at most) needs no index; add one later if it ever
matters.

Migration: `alembic revision --autogenerate` for the four columns, plus a
hand-added `op.execute("CREATE EXTENSION IF NOT EXISTS vector")` at the top
of the migration (autogenerate won't emit this — it's a database-level
extension, not a table change; every other statement in the migration stays
autogenerated). This is the one place `backend/CLAUDE.md`'s "migrations
directory is autogenerated-only" rule needs a deliberate, documented
exception, same category as 3a's `CREATE DATABASE` fixture code being the
plan's one acknowledged exception to a general rule.

## Populating `price_at_recommendation`

`AnalysisState` (`agents/graph.py`) already carries `quote: dict[str, Any]`
(`{"price": float | None, "closes": list[float]}`) all the way through to
the graph's final returned state — `agents/jobs.py`'s `_process_ticker`
already receives that full state after `run_graph_for_ticker` returns, it
just doesn't currently read `state["quote"]["price"]` when building the
`Recommendation` row. This is a one-line addition to the existing
`Recommendation(...)` constructor call in `_process_ticker` —
`price_at_recommendation=state["quote"]["price"]` — no new fetch, no
`AnalysisState` change, no `graph.py` change at all.

## `backend/app/memory/embeddings.py`

```python
async def embed_text(text: str) -> list[float]:
```
Wraps Voyage AI's embed endpoint (`model="voyage-finance-2"`), returns the
1024-dim vector. Raises on failure (missing API key, network error) — the
two router handlers that call it are what decide whether that's a
per-row-skip (batch endpoints) or a request-level 503 (`/memory/similar`,
which has nothing useful to return without an embedding).

`Settings` gains `voyage_api_key: str | None = None`; `.env.example` gains
`VOYAGE_API_KEY=`.

## `backend/app/memory/outcomes.py`

```python
async def compute_outcome(ticker: str, price_at_recommendation: float) -> float:
```
Fetches the current price via `market_data.fetch_quote_and_history(ticker)`
and returns `(current_price - price_at_recommendation) / price_at_recommendation`.
No lookback-window logic here — the caller (`/memory/evaluate-outcomes`)
decides which rows are due; this function just computes one outcome given
one already-past-due row.

## `backend/app/memory/similarity.py`

```python
def find_similar(db: Session, query_embedding: list[float], top_k: int) -> list[Recommendation]:
```
`db.query(Recommendation).filter(Recommendation.user_id == settings.default_user_id, Recommendation.embedding.isnot(None)).order_by(Recommendation.embedding.cosine_distance(query_embedding)).limit(top_k).all()`
— `pgvector.sqlalchemy`'s `cosine_distance` comparator generates the `<=>`
operator SQL directly; no raw SQL string needed.

## `backend/app/routers/memory.py`

```
POST /memory/embed
  -> scans Recommendation WHERE user_id = default_user_id AND embedding IS NULL,
     batch of up to 50, builds situation text per row
     ("{ticker} ({asset_type}): {action}. {'; '.join(reasoning)}." plus
     ai_analysis if present), calls embed_text(), stores embedding, commits
     per row (one row's embedding failure doesn't lose the others already
     committed)
  -> on missing VOYAGE_API_KEY: 503 before touching any row
  -> {"embedded": N, "remaining": M}   # M = count still NULL after this batch

POST /memory/evaluate-outcomes
  -> scans Recommendation WHERE user_id = default_user_id
     AND outcome_evaluated_at IS NULL
     AND price_at_recommendation IS NOT NULL
     AND created_at <= now() - 20 days
     batch of up to 50, calls compute_outcome() per row, stores
     outcome_forward_return_pct + outcome_evaluated_at = now(), commits per row
  -> {"evaluated": N, "remaining": M}

POST /memory/similar {"query": str, "top_k": int = 5}
  -> embed_text(query), find_similar(...), returns matches with their
     ticker/action/reasoning/outcome fields (a new MemorySimilarOut schema:
     the same subset of RecommendationOut's fields plus
     outcome_forward_return_pct)
  -> on missing VOYAGE_API_KEY: 503
```

Sanitized error handling matches `agents/jobs.py`'s established pattern:
a per-row exception inside either batch endpoint is caught, logged via
`logger.exception`, and that row is skipped (still counted toward the
batch's processed total, just not toward `embedded`/`evaluated`) — one bad
row never aborts the rest of the batch.

## Testing

- `memory/embeddings.py` — mocks the Voyage client, never a real API call
  in the automated suite (same rule as `yfinance`/Anthropic elsewhere in
  this project).
- `memory/outcomes.py` — mocks `fetch_quote_and_history`.
- `memory/similarity.py` — real Postgres test DB (already available via
  3a), synthetic embedding vectors (e.g. orthogonal unit vectors with known
  relative distances) to verify `pgvector`'s ordering is actually correct —
  no mocking, matching the existing `BacktestResult` JSON round-trip test's
  precedent for testing real DB-native behavior.
- `routers/memory.py` — `TestClient` + mocked service-layer functions, same
  pattern as `routers/analysis.py`/`routers/backtest.py`.
- `agents/jobs.py`'s existing tests gain one assertion:
  `price_at_recommendation` is set on the created `Recommendation` row.
